# 健身房門市營運異常分析（SQL）

用 MySQL 從門市銷售資料中找出成交率異常，逐層拆解根因，排除外部干擾、驗證假設，並估算營收影響。

> 資料為自行生成的模擬資料，情境依照本人 8 年健身房營運經驗設計。分析方法與業務判斷為本人完成。

## 結論摘要

- **問題**：B店 2025 年 8–9 月成交率從平常約 0.43 掉到 0.22，10 月恢復。
- **根因位置**：只有 B店的教練課（10 堂、30 堂）下跌，月費會員正常；同期 A店教練課也正常 → 屬於門市層級的問題。
- **最弱環節**：陌生客（FB私訊、路過）成交率只剩 0.02–0.08；會員介紹仍有 0.26–0.28。
- **排除干擾**：活動影響很大（有活動 0.52、無活動 0.39）。只比無活動期間，並排除 8–9 月後，B店為 0.42、A店為 0.39，B店平常並不差。
- **假設驗證**：「7 月活動提前消化需求」不成立，因為 8 月諮詢數 372，高於平常。問題是**來了卻沒成交**。
- **影響估算**：如果維持正常成交率，8–9 月應多成交約 164 筆，估計營收損失約 326 萬元。

## 下一步建議

這份資料無法直接證明根因，需要調閱以下紀錄：

| 假設 | 需要的資料 |
|---|---|
| 教練請假、出國，或人力不足 | 8–9 月教練排班表、請假紀錄 |
| 新客可上課時段與教練時段媒合不上 | 預約紀錄、未成交原因紀錄 |

## 分析流程

| 步驟 | 問題 | 方法 | 檔案 |
|---|---|---|---|
| 清理 | 資料能用嗎？ | TRIM、REGEXP、NULLIF、CAST、DISTINCT | `01_setup_and_clean.sql` |
| A 發現 | 哪個月不正常？ | 以「該店無活動月份平均」為基準，低 30% 以上視為異常 | `02_analysis.sql` |
| B 定位 | 哪個方案、哪個來源？ | 方案 × 來源拆解，並以 A店作對照組 | 同上 |
| C 排除 | 是不是活動造成的？ | 有／無活動比較，只在相同條件下比較門市 | 同上 |
| D 驗證 | 是需求變少，還是沒成交？ | 分開看諮詢數與成交數 | 同上 |
| E 影響 | 損失多少？ | 以正常成交率推估應有成交數 × 平均客單價 | 同上 |

## 資料清理紀錄

原始 2,450 筆，清理後 2,446 筆：

- 門市名稱多出空白 1 筆 → TRIM 修正
- 諮詢數為中文「三」1 筆 → 排除（無法確認原始數值）
- 成交數空白 1 筆 → 排除
- 營收空白 1 筆 → 保留，營收設為 NULL（不影響成交率計算）
- 完全重複 2 筆 → 去除

## 資料欄位

`sale_date` 日期｜`store` 門市｜`plan` 方案（月費會員、教練課10堂、教練課30堂）｜`source` 來源（FB私訊、路過、會員介紹）｜`promo` 是否有活動（Y/N）｜`inquiries` 諮詢數｜`deals` 成交數｜`revenue` 營收

## 如何執行

```bash
docker run -d --name gym-mysql -e MYSQL_ROOT_PASSWORD=<你的密碼> -p 3310:3306 mysql:8.0
docker cp data/gym_2025.csv gym-mysql:/var/lib/mysql-files/gym_2025.csv
docker exec -i gym-mysql mysql -uroot -p --default-character-set=utf8mb4 < sql/01_setup_and_clean.sql
docker exec -i gym-mysql mysql -uroot -p --default-character-set=utf8mb4 < sql/02_analysis.sql
```

工具：MySQL 8.0、Docker
